# Badsoffware

**V2 (current)**: 2-4 player online tag game, portrait phone screens. Robots (Patch, Bolt, Glitch,
Havoc; Rumble and Nova benched) climb a 2-screen city tower for 1-3 minutes, It passed on by a
touch. Least total time as It wins. Catch a Badsoffware drone (Bopster/Grumpulator/Sneakfolder/
Hijacker) for a one-shot power-up. `docs/PRD_v2.md` has the v2 spec this was built from (the
linked Claude Docs page it names is the source of truth; the markdown is an offline copy).
Rebuild the art pack and run the checks:

    python3 tools/process_bswv21.py <raw BSWV21 zips extracted here> art
    python3 tools/embed_art_v2.py
    node test/run_all.mjs   # needs a local server on :8123, see "Run locally" below

**V1 (superseded by the above)**: 2-player online tag game. One self-contained `index.html`, vanilla JS and Canvas 2D, no build step.
Two mecha pilots (pick from Patch, Bolt, Glitch, Rumble, Nova and Havoc; all handle identically) chase each other round a dark computer desktop for 2 minutes. Most tags wins. The sections below still apply to v2 unless noted (run locally, deploy, tuning).

**CLIMB (solo, prototype)**: `climb.html`, a separate single-player mode. Climb a procedurally generated tower while a swarm of Badsoffwares builds itself upwards to consume you. A hunter drone peels off now and then (stomp it, dodge it, or shock it). Skip platforms for a combo, catch drones for one-shot items (freeze, shock, shield, jet). Daily seed (MYT) gives everyone the same tower. Open `http://localhost:8123/climb.html`. Tunables are in `CONFIG` at the top of the script; `node test/climb_mode.mjs` runs a scripted bot through it.

## Run locally
Never open the file directly. Serve it:

    npx serve .            # or
    python3 -m http.server 8123

Then open `http://localhost:8123/` (landscape, or a wide desktop window).

Keyboard: A/D or arrows move, W/Up/Space jump (double jump allowed), S/Down drops through a window, P pauses, M mutes.

## Play
- **Practice**: DEPLOY, then PRACTICE VS BOT. Works offline once the page has loaded.
- **Two phones, same Wi-Fi**: one taps HOST GAME and reads out the 4 letter room code. The other taps JOIN GAME and types it on the on-screen keypad. Pick pilots, both tap I'M READY.
- Peer-to-peer connects reliably on the same Wi-Fi. Between phones on different mobile networks it can fail without a TURN relay (v1 targets same-Wi-Fi play). To add a relay, fill `PEER_HOST`, `PEER_PORT` and `ICE_SERVERS` in `CONFIG`.

## Testing two players with two tabs (no internet needed)
Open `http://localhost:8123/?net=tabs` in two tabs of the same browser. Tab 1: DEPLOY, HOST GAME. Tab 2: DEPLOY, JOIN GAME, type the code (keyboard works) and press Enter. This uses a BroadcastChannel transport behind the same `Net` interface.

Same-screen two-player debug: `?debug=2p`, then the "2P SAME SCREEN" button on the connect screen (P1 = WASD, P2 = arrows).

## Deploy
Needs https for fullscreen, wake lock and WebRTC.
- Netlify Drop: drag this folder onto https://app.netlify.com/drop
- GitHub Pages: the built game lives on the `gh-pages` branch. Repo Settings > Pages > Deploy from a branch > `gh-pages` / `(root)`. Live at https://soffianz.github.io/badsoffware/ . After changing `index.html`, run `tools/deploy_pages.sh` to republish.

## Publishing as a claude.ai artifact (optional ClaudeRoom transport)
If `window.claude.use("room")` resolves within 3 s, the game uses it instead of PeerJS and skips room codes (both players tap PLAY ONLINE). Needs the artifact published with `capabilities: {room: {}}` and every player signed in to claude.ai. Outside network calls, PeerJS included, are blocked inside published artifacts, which is why this transport exists.

## Automated checks (optional, need Playwright)
With a server on :8123: `node test/smoke.mjs` (screens + bot round), `node test/net.mjs` (two-tab host/guest, tags, pickups, pause, drop and rejoin, rematch), `node test/extra.mjs` (bot, windows, pilot conflict, mocked ClaudeRoom), `node test/touch.mjs` (multi-touch, drop-through, portrait), `node test/physics.mjs`.

## Art
The prototype desktop background is embedded in `index.html`. Rebuild it with `python3 tools/make_bg.py && python3 tools/embed_art.py`. Pilot and drone sprites are generated by `node tools/make_sprites.mjs` (needs a server on :8123) and embedded with `python3 tools/embed_art.py`. See `assets/` and the Art section of `DECISIONS.md`.

## Tuning
Every number (physics, timings, sizes, colours) lives in the `CONFIG` object at the top of the script.

## Weapons
Each pilot has a unique weapon. Catch a rogue app drone to get 2 charges. Touch: hex button above JUMP. Keyboard: E, F or Left Shift (Right Shift also works in solo play). See DECISIONS.md.

## Tower
The desktop is a tower three screens tall. Jump up the windows to escape; step off an edge and you drop straight down, no damage. An arrow shows where the other pilot is when they are off screen.
